# OffsetDraw Product Experience Roadmap

## 1. Short Conclusion

OffsetDraw 下一阶段不应优先堆绘图功能，而应先把“手机上可持续慢画”的完整体验做扎实。

当前项目已经具备作品库、自动保存、颜色、稳定器和导出，技术闭环基本成立。接下来真正影响产品质量的是：画布是否干净、工具是否打扰创作、作品是否容易找回、慢画手感是否经过真机校准。

建议下一阶段目标定义为：沉浸绘画工作台。

## 2. Current Product Shape

### 已经成立的体验闭环

- 用户可以新建作品。
- 用户可以进入画布绘制。
- 用户可以通过偏移笔尖和稳定器慢速画线。
- 用户可以修改画笔颜色、画板颜色和笔触参数。
- 用户可以撤销、清空、导出。
- 用户的笔画和配置会自动保存。

### 当前主要问题

- 画布工作区被底部工具栏长期占据，创作时有压迫感。
- 工具和参数没有分层，常用动作与低频调参混在一起。
- 首页只有文本列表，缺少绘画产品应有的视觉识别。
- 核心手感还没有形成经过真机验证的默认值。
- 功能继续扩展前，产品重心还需要从“原型可用”转向“长期可画”。

## 3. Priority 1: 绘画工作台整体性

### 目标

让用户进入作品后，第一感受是“我在画画”，而不是“我在操作一组调试控件”。

### 核心判断

当前最需要优化的是绘画状态下的视觉秩序。画布应该是主角，工具应该只在必要时出现。参数面板不应长期占据画布，也不应和撤销、导出这类动作平级。

### 建议范围

- 把底部工具栏拆成两层：
  - 常驻层：撤销、画笔、颜色、更多。
  - 展开层：笔宽、稳定半径、移动倍率、平滑程度、画板颜色、导出、清空。
- 默认进入作品时展示最小工具条。
- 参数面板可展开、可收起。
- 危险动作如清空需要二次确认。
- 工具状态要可见，例如当前颜色、当前笔宽、是否处于绘制准备状态。

### 不建议现在做

- 不先做复杂笔刷商店。
- 不先做图层面板。
- 不先做大而全的设置页。

### 验收标准

- 用户可以在不理解参数含义的情况下直接开始画。
- 绘画时画布占据主要视觉空间。
- 常用动作一眼可见，低频设置不干扰创作。
- iPhone 小屏上工具不遮挡主要绘制区域。

## 4. Priority 2: 作品管理可信感

### 目标

让用户相信自己的作品被保存了，并且能快速找回、识别、继续编辑。

### 核心判断

绘画产品的首页不能只是文件索引。用户找作品时主要靠视觉记忆，不靠文件名和日期。当前文本列表能证明“文件存在”，但不能建立“这是我的作品集”的感觉。

### 建议范围

- 首页显示作品缩略图。
- 支持重命名。
- 支持删除。
- 支持复制作品。
- 空状态只保留最小必要入口，不添加解释性废话。
- 列表或网格需要体现最近编辑顺序。

### 缩略图策略

- 主存储仍然保留 stroke JSON。
- 缩略图作为派生缓存，不作为作品真源。
- 每次保存作品后更新缩略图，或在首页需要时懒生成。
- 缩略图失效时可以重新从 stroke 渲染。

### 不建议现在做

- 不引入云同步。
- 不做复杂文件夹系统。
- 不做分享社区。

### 验收标准

- 用户不用打开作品，也能识别大部分画稿。
- 误删风险可控。
- 复制作品不会破坏原稿。
- 首页从“工程列表”变成“作品入口”。

## 5. Priority 3: 输入手感验证

### 目标

把 OffsetDraw 的核心差异点验证清楚：偏移笔尖、长按落笔、拉绳稳定器是否真的适合手机慢画。

### 核心判断

这个项目的竞争力不是功能数量，而是输入手感。如果手感没有被真机验证，继续增加橡皮擦、图层、笔刷都会放大不确定性。

### 必须验证的问题

- 长按落笔是否打断创作节奏。
- 默认稳定半径是否过大或过小。
- 移动倍率默认值是否让人感觉可控。
- 平滑程度是否导致线条明显滞后。
- 蓝色稳定线是否帮助理解，还是干扰画面。
- 静止笔尖是否让用户知道下一笔会从哪里开始。

### 建议方法

- 先用真机画 5 分钟，不改代码，只记录不适感。
- 每次只调整一个参数。
- 改动后立刻回到真机验证。
- 不在模拟器里判断最终手感。

### 可能的产品决策

- 长按落笔保留，但缩短等待时间。
- 长按落笔改为可选模式。
- 稳定线默认只在拖拽距离超过阈值时显示。
- 提供 2-3 个手感预设，而不是暴露所有参数。

### 验收标准

- 用户能稳定画出慢速线条。
- 第一笔不会因为交互规则而困惑。
- 默认参数不需要用户先调一轮才能使用。
- 核心手感可以被一句话描述清楚。

## 6. Priority 4: 绘图能力扩展

### 目标

在核心工作台和手感稳定后，再扩展真正提升创作能力的绘图功能。

### 核心判断

绘图能力扩展应该服务于“完成一张画”，而不是服务于“看起来功能很多”。下一步可以做橡皮擦和笔刷预设，但不应早于工作台整理与手感验证。

### 推荐顺序

1. 橡皮擦
2. 笔刷预设
3. 画布尺寸或比例
4. 透明背景导出
5. 图层

### 橡皮擦策略

- 初期可以作为一种特殊 stroke，而不是直接修改位图。
- 保持撤销逻辑简单。
- 保持作品仍可从 stroke 数据恢复。

### 笔刷预设策略

- 先做少量预设，例如细线、普通、粗线、慢画。
- 预设应改变参数组合，而不是让用户逐项理解所有滑杆。
- 保留高级参数，但默认隐藏。

### 图层策略

- 图层是高复杂度功能，涉及数据结构、渲染顺序、选择状态、合并、删除、导出。
- 在没有稳定工作台之前，不建议启动图层。

### 验收标准

- 新增能力不会破坏现有慢画体验。
- 每个功能都能进入自动保存、撤销、导出闭环。
- UI 不因为新增功能重新变成参数堆叠。

## 7. Recommended Next Phase

下一阶段建议只做一个阶段目标：沉浸绘画工作台。

范围：

- 收起式工具栏。
- 工具分层。
- 首页缩略图。
- 作品重命名、删除、复制。
- 真机手感参数校准。

暂缓：

- 图层。
- 云同步。
- 复杂笔刷。
- 社区分享。
- 大型设置页。

## 8. Product Flow

```text
打开 App
  -> 看到作品缩略图
  -> 新建或继续作品
  -> 进入干净画布
  -> 用最少工具开始画
  -> 需要调参时展开面板
  -> 自动保存
  -> 回到首页后能看到更新后的作品
```

## 9. Sequential Flows

### Flow A: 绘画主流程

```text
进入作品 -> 干净画布 -> 画一笔舒服的线
```

语义闭环：用户能不被工具打扰地完成绘制。

### Flow B: 作品找回流程

```text
打开首页 -> 通过缩略图识别作品 -> 继续编辑
```

语义闭环：用户相信作品存在，并能快速回到创作。

### Flow C: 参数调整流程

```text
发现手感不合适 -> 展开参数 -> 调整后立即试画
```

语义闭环：调参服务于画线，而不是成为主要任务。

### Flow D: 能力扩展流程

```text
稳定工作台 -> 增加单一绘图能力 -> 纳入保存和撤销
```

语义闭环：每次新增能力都必须回到完整创作闭环。

## 10. Decision Rule

之后每个新需求都先问一个问题：

这个改动是在减少画画时的阻力，还是只是在增加功能数量？

如果答案是前者，优先做。如果答案是后者，等核心工作台稳定后再做。
